`@pytest.mark.str` is almost certainly a **custom marker** your project or course is using to label certain tests, but it has
no special built‑in meaning in `pytest` itself. Like `@pytest.mark.sanity`, it just **tags** the test so you can later run or
filter by that label.

### What this marker usually means

In practice, `str` is often short for:

- **“string” tests** (tests that exercise string handling), or
- **“structural” / “structure”** tests, or
- an arbitrary label chosen by the course / team (e.g., `@pytest.mark.str` = “short tests” or “simple tests”).

The exact meaning depends entirely on how the course or project defines it in `pytest.ini` or in documentation.

### How it is used

Example:

```python
import pytest

@pytest.mark.str
def test_trim_whitespace():
    assert "  hello  ".strip() == "hello"
```

Then you can run only those tests:

```bash
pytest -m str
```

or skip them:

```bash
pytest -m "not str"
```

To see what `str` is officially intended to mean in your environment, check your `pytest.ini` or any marker‑registration
section where it’s documented (for example under `[pytest] markers =`); that’s where your course or project should define its
custom markers.
