In pytest fixtures, the `yield` keyword enables setup code before tests run and teardown (cleanup) code afterward, acting
like a generator that pauses execution at `yield`. This replaces older `yieldfixture` syntax and provides automatic resource
management, such as creating a test database connection before `yield` and closing it after.
[stackoverflow](https://stackoverflow.com/questions/77318902/why-using-yield-instead-of-return-in-pytest-fixtures/78849260)

## Basic Usage

Define a fixture with `@pytest.fixture`, place setup code before `yield value` (where `value` is passed to the test), and
teardown after. Tests receive the yielded value as a parameter; pytest ensures teardown runs even if tests fail. For no
return value, use `yield` alone.
[campus.datacamp](https://campus.datacamp.com/courses/introduction-to-testing-in-python/pytest-fixtures?ex=11)

Example:

```
@pytest.fixture
def temp_db():
    conn = create_connection()  # Setup
    yield conn                 # Test uses conn
    conn.close()               # Teardown
```

## Vs Return

`return` skips teardown—use it for simple fixtures without cleanup. `yield` is essential for resources needing finalization,
like files or mocks, ensuring tests don't leak state.
[stackoverflow](https://stackoverflow.com/questions/77318902/why-using-yield-instead-of-return-in-pytest-fixtures)
