In pytest-bdd, "Cucumber" refers to the broader software ecosystem and standards that established Behavior-Driven Development
(BDD). While pytest-bdd is a specific Python plugin for the pytest runner, it is heavily influenced by and compatible with
Cucumber-style testing. [1, 2, 3, 4] Specifically, "Cucumber" in this context typically means:

## 1. The Gherkin Language [5]

pytest-bdd uses Gherkin, the plain-text language originally created for Cucumber. This allows you to write test scenarios in
human-readable English using keywords like: [5, 6, 7]

- Feature: Describes the high-level functionality being tested.
- Scenario: A specific example of that functionality.
- Given, When, Then: Steps that define the setup, action, and expected outcome. [3, 8, 9, 10, 11]

## 2. Cucumber Expressions

Modern versions of pytest-bdd (and especially pytest-bdd-ng) support Cucumber Expressions. These are a user-friendly
alternative to Regular Expressions for matching steps in your .feature files to your Python code. [12, 13, 14]

- Example: Using {int} or {string} placeholders to automatically capture data from a step. [12, 15, 16]

## 3. Standardized Reporting

pytest-bdd can generate test reports in the Cucumber JSON format. This allows you to use common Cucumber ecosystem tools—like
Jenkins plugins or Allure—to visualize your test results in a way that is consistent across different programming languages.
[17, 18, 19, 20]

## 4. Why Use "Cucumbers" in Examples?

You will often see the word "cucumbers" used in documentation examples (e.g., "Given there are 5 cucumbers in the basket").
This is a traditional naming convention in the BDD community, used as a playful nod to the Cucumber framework itself. [15,
