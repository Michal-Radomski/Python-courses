`@pytest.mark.sanity` is a **custom marker** you add to a test to label it as a “sanity” test, i.e., a small, quick,
high‑priority check that the most important features are working. It doesn’t change how the test behaves; it only **tags** it
so you can run just these tests later.
[neovasolutions](https://www.neovasolutions.com/2023/03/02/how-to-run-a-test-suite-in-pytest/)

### What it does in practice

- It categorizes tests:

  ```python
  import pytest

  @pytest.mark.sanity
  def test_login():
      assert True  # example

  @pytest.mark.sanity
  def test_homepage_loads():
      assert True
  ```

- You can then run **only** the sanity tests from the command line:

  ```bash
  pytest -m sanity
  ```

  This runs only functions decorated with `@pytest.mark.sanity`. [kazis](https://www.kazis.dev/blogs/pytest-custom-markers)

- You can also skip them:
  ```bash
  pytest -m "not sanity"
  ```

### Note about warnings

If you see a warning like “unknown marker ‘sanity’”, you should register it in `pytest.ini` (or `pyproject.toml`) to avoid
that warning:

```ini
[pytest]
markers =
    sanity: Run only basic sanity checks
```

This keeps your markers well‑documented and suppresses pytest warnings.
[docs.pytest](https://docs.pytest.org/en/stable/how-to/mark.html)
