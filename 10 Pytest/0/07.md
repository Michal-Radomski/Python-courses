`@pytest.mark.xfail` means: **“This test is expected to fail, but please still run it.”**

It is used when you know a test should fail (for example, a bug is not yet fixed or a feature is not yet implemented), but
you still want:

- the test to run,
- the test result to be recorded as “expected fail” (XFAIL),
- and the overall test suite to still pass.

### How it behaves

- If the test **fails** (as expected):
  - It is marked as `XFAIL` in the output.
  - The suite still passes.

- If the test **unexpectedly passes**:
  - It is marked as `XPASS` (unexpected pass).
  - By default this still does **not** make the suite fail, unless you set `strict=True` (then `XPASS` fails the suite).
    [docs.pytest](https://docs.pytest.org/en/7.1.x/reference/reference.html)

### Example usage

```python
import pytest

@pytest.mark.xfail(reason="known bug: feature not implemented yet")
def test_not_implemented_yet():
    assert 1 == 2
```

Then run:

```bash
pytest -v
```

You will see that test reported as `XFAIL`, but the run still passes.
[docs.pytest](https://docs.pytest.org/en/stable/how-to/skipping.html)

### When to use `xfail` vs `skip`

- Use `@pytest.mark.xfail` if you want to **run** the test and track whether it unexpectedly starts to work.
- Use `@pytest.mark.skip` if you want to **completely skip** running the test.
  [stackoverflow](https://stackoverflow.com/questions/76838648/pytest-mark-skip-vs-pytest-mark-xfail-in-pytest)
