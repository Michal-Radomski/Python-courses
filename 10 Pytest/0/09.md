Pytest fixtures provide reusable setup and teardown code for tests, eliminating boilerplate like repeated database
connections or mock data preparation. They use dependency injection, where tests declare fixtures as arguments, and pytest
automatically resolves and injects them. [docs.pytest](https://docs.pytest.org/en/stable/how-to/fixtures.html)

## Defining Fixtures

Use the `@pytest.fixture` decorator on a function to create one; it can return data or use `yield` for cleanup after the test
runs. For example, a fixture might initialize a temporary database, run the test with it, then drop the tables. Scopes like
`function`, `module`, `class`, or `session` control reuse—`session` runs once per test session for efficiency.
[stackoverflow](https://stackoverflow.com/questions/62376252/when-to-use-pytest-fixtures)

## Using Fixtures

Tests "request" fixtures by including their names as parameters—pytest matches and executes them in dependency order before
the test. Fixtures support parametrization for data-driven tests and can depend on other fixtures for modularity. Unlike
plain functions, fixtures handle caching, lifetimes, and automatic teardown.

## Key Benefits

Fixtures replace `setup/teardown` methods from other frameworks (like unittest), offering more flexibility, such as autouse
fixtures that run without explicit requests. They speed up tests by sharing expensive resources across multiple tests within
a scope. [pytest-with-eric](https://pytest-with-eric.com/fixtures/pytest-fixtures/)
