To exclude an `env` directory (for example a virtual‑env folder like `env/` or `.venv/`) from being scanned by `pytest`, you
have two typical options.

### 1. Command‑line: `--ignore`

Run `pytest` with the `--ignore` flag:

```bash
pytest --ignore=env/
```

This tells `pytest` not to collect tests from the `env/` directory at runtime.
[betterstack](https://betterstack.com/community/questions/how-to-use-pytest-with-virtualenv/) You can ignore multiple paths
by adding more `--ignore` options:

```bash
pytest --ignore=env/ --ignore=venv/
```

### 2. Permanent config: `norecursedirs` or `ignore` in config

In a config file such as `pytest.ini`, `pyproject.toml`, or `setup.cfg`, you can permanently exclude `env/`.

#### Using `pytest.ini`

```ini
[pytest]
norecursedirs = env venv .venv .git __pycache__ build dist
```

This stops `pytest` from recursing into those directories altogether.
[woteq](https://woteq.com/how-to-customize-pytest-test-discovery-in-python/)

#### Using `pyproject.toml`

```toml
[tool.pytest.ini_options]
norecursedirs = ["env", "venv", ".venv", ".git", "__pycache__", "build", "dist"]
```

Alternatively you can list them under `addopts` with `--ignore`:

```toml
[tool.pytest.ini_options]
addopts = [
  "--ignore=env",
  "--ignore=venv"
]
```
