JWT logout isn't like session-based auth since tokens are stateless and can't be directly revoked server-side. Common flows
rely on blacklisting, short expiration, or client-side token deletion.

## Client-Side Logout

Clear the JWT from browser storage (localStorage, sessionStorage, or cookies) and redirect to login. The token remains valid
until expiry if stolen, but user access ends immediately.[1][2]

## Server-Side Blacklisting

Add the token to a server blacklist (e.g., Redis set, database, or in-memory cache) on logout. Update auth middleware to
check if incoming tokens are blacklisted before verifying signature/expiry. Clean up expired tokens periodically.[4][5]

## Short-Lived Tokens + Refresh

Issue access tokens with brief expiry (e.g., 15-60 minutes) and use refresh tokens for renewal. On logout, blacklist the
refresh token only; access tokens die naturally. Pairs well with "fresh" claims from prior context.[3][1]
