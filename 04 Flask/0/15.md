Redis background workers use Redis as a message broker to manage queues of asynchronous tasks processed by dedicated worker
processes, keeping web apps responsive by offloading slow jobs like email sending or image processing.[1][2]

## Core Concept

Background workers run continuously as separate services that poll a Redis queue for jobs pushed by your main Flask app.
Common frameworks include Celery (Python), RQ, or Sidekiq (Ruby), where Redis stores job data like task names, arguments, and
status.[8][1]

## Flask Integration Example

With prior Redis setup, add Celery for workers.

```
pip install celery
```

`celery_app.py`:

```python
from celery import Celery
celery = Celery('app', broker=os.environ.get('REDIS_URL'))
@celery.task
def send_background_email(to, subject, message):
    # Use Mailgun code here
    pass
```

In Flask route: `send_background_email.delay(to, subject, message)`.[1]

## Deployment on Render

Create a Background Worker service linked to your Flask repo's Redis.

- `Procfile`: `worker: celery -A celery_app worker --loglevel=info`
- Set `REDIS_URL` env var.  
  Scale workers independently via dashboard.[1]
