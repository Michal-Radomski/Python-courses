In JWT (JSON Web Tokens), the "fresh" flag is a custom claim used in certain authentication libraries like Flask-JWT-Extended
or FastAPI-JWT-Auth to indicate the token's "freshness" status.[1][2]

## Fresh: True

A token marked `fresh: true` is newly issued after direct user authentication (e.g., via username/password login), confirming
recent credential verification. It grants access to sensitive endpoints protected by `@jwt_required(fresh=True)`.[2][1]

## Fresh: False

A token with `fresh: false` is typically generated from a refresh token without re-verifying credentials, so it cannot access
fresh-required endpoints. This enhances security by limiting non-fresh tokens to less critical actions.[1][2]

## Usage Context

This pattern pairs with refresh tokens: login creates a fresh access token; refresh creates a non-fresh one to avoid frequent
logins while protecting high-risk operations. It's not a standard JWT claim but a library-specific extension.[2][1]
