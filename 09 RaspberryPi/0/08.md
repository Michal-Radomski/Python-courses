**MQTT stands for Message Queuing Telemetry Transport.** It's a lightweight publish-subscribe messaging protocol ideal for
IoT devices with limited bandwidth or power. [en.wikipedia](https://en.wikipedia.org/wiki/MQTT)

## How It Works

Devices connect to a central **MQTT broker** (like Mosquitto). **Publishers** send messages to **topics** (e.g.,
"home/temperature"), and **subscribers** receive them via those topics—decoupling sender and receiver for scalability.
[cisco](https://www.cisco.com/site/us/en/learn/topics/networking/what-is-message-queuing-telemetry-transport-mqtt.html)

## Key Features

- **Lightweight**: Minimal overhead (2-byte header minimum) for constrained networks.
  [en.wikipedia](https://en.wikipedia.org/wiki/MQTT)
- **QoS Levels**: 0 (at most once), 1 (at least once), 2 (exactly once) for reliability.
  [emqx](https://www.emqx.com/en/blog/the-easiest-guide-to-getting-started-with-mqtt)
- **Runs over TCP/IP**: Secure with TLS; supports last will and testament for device status.
  [aws.amazon](https://aws.amazon.com/what-is/mqtt/)

## Use Cases

Perfect for Raspberry Pi projects like remote sensors publishing data to a broker, which dashboards subscribe to—seen in
smart homes, industry monitoring. Open standard (OASIS/ISO) since 2019. [en.wikipedia](https://en.wikipedia.org/wiki/MQTT)
